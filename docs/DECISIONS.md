# Принятые решения

Здесь сохранены действующие решения. Их идентификаторы оставлены для сопоставления с историей; отменённые версии исключены. Пользовательский сценарий описан в [PRODUCT.md](PRODUCT.md).

| Решения | Причина и действующее правило |
| --- | --- |
| ADR-001, 002, 013 | Подбирается конкретный план с временем и местом. Выбор приглашения — единственный этап согласия, без дополнительного голосования. |
| ADR-004 | Near поддерживается для бюджета и всегда требует отдельного согласия. Автоматического принятия исключения нет. |
| ADR-005 | Расстояние считается в километрах от собственной выбранной точки; минуты в пути не обещаются. |
| ADR-006, 023 | Автосигнал сохраняется, но не означает участия. Правило использует IANA timezone, полный местный интервал и переход через полночь. |
| ADR-007 | Города ограничены достаточностью данных, а не единственным городом пилота. |
| ADR-008 | AI не нужен для детерминированного подбора и не входит в продукт. |
| ADR-009, 011, 012 | KudaGo за адаптером, React/Vite, FastAPI и PostgreSQL; модульный монолит соответствует масштабу MVP. |
| ADR-010 | Приватность обеспечивается на backend: чужие исходные условия не попадают в ответы. |
| ADR-014, 015 | Полный пул приглашений охватывает все компании пользователя. Ранжирование не выбирает друзей и не скрывает подходящие приглашения. |
| ADR-016, 017, 021 | Redis кеширует реальные выборки город/время/категории; PostgreSQL хранит снимок только созданного плана. Бюджет и радиус необязательны. |
| ADR-018, 020 | Отсутствующие необязательные поля не показываются. Недостающий факт для заданного ограничения означает Unverified, а не Conflict; приглашения и плана только из таких оценок нет. |

## ADR-024 — Открытый план и точная очередь

Приглашения получают все совместимые участники. План может начать один подходящий человек, но подтверждение требует допустимого состава. «Неважно» означает минимум 2; без личного максимума вместимость равна размеру Компании. План подтверждается при минимуме и принимает участников до вместимости или закрытия приёма. Для «Ровно N» действуют порядок успешных ответов и личная очередь; отмена продвигает первого подходящего ожидающего. Личный минимум выше текущей вместимости не даёт приглашения.

## ADR-025 — Один пакет Сигнала, один город

Разовый Сигнал может адресоваться нескольким компаниям одного города. Город берётся из Компании; создание, изменение и отмена пакета атомарны. Срок рассчитывается сервером. Радиус требует собственной реальной точки в том же городе.

## ADR-026 — Периодическая проверка и факты провайдера

Автосигнал проверяется после создания/изменения/возобновления и планировщиком. Events и Places нормализуются отдельно. Каждое событие требует достоверного конца; место получает конкретный слот. Цена FROM остаётся нижней границей, UNKNOWN блокирует только заданный бюджет. Параметры по умолчанию: интервал 30 минут и горизонт семь дней.

## ADR-027 — Необязательный срок ссылки

`invite_expires_at` может быть NULL. Скрытого срока жизни нет. У явно истёкшего токена ответ `410`, у неизвестного — `404`.

## ADR-028 — Подтверждённое ядро и условные ответы

Более строгий минимум нового ответившего не отменяет уже допустимый состав. Он остаётся `WAITING_CONDITION`, пока возможный состав не удовлетворит и его диапазону. Пересчёт сначала сохраняет уже принятых участников, затем предпочитает наибольший допустимый состав; равенство разрешается порядком ответа. Отмена может вернуть часть участников в условное ожидание, сохранив оставшееся допустимое ядро. Имена и публичный счётчик включают только `ACCEPTED`, личное условие остаётся владельцу.

## ADR-029 — Слот места и категория «Бани и спа»

На ограниченной сетке для каждого места и местного дня выбирается слот с наибольшим допустимым составом, затем с наибольшим числом совместимых людей, затем самый ранний. Создаётся один вариант на место/день. Категория `wellness` использует категории KudaGo вместе с тематическими словами; сырые slug провайдера не служат основными категориями интерфейса.

## ADR-030 — Сохранённые места и согласованность пакета

Места приватны и привязаны к городу; одна точка может быть default для владельца в городе. Используемую активным Сигналом точку нельзя удалить. Запрос провайдера предшествует транзакции записи пакета, условия и пересчёт фиксируются вместе. Ошибка пересчёта откатывает пакет; повторный refresh идемпотентен.

## ADR-031 — Явная смена города Компании

Только владелец выбирает город из актуального списка провайдера. В одной транзакции меняются город/timezone, отменяются активные разовые Сигналы и собираемые планы, приостанавливаются Автосигналы и закрываются соответствующие приглашения. `CONFIRMED_OPEN` сохраняет принятый состав и исходные факты, но его pending/conditional/waitlisted приглашения больше не собирают людей. Подтверждённые планы и сохранённые места не переписываются.
