# Как использовать этот pack

Этот pack разделяет работу с Codex/агентом на два этапа.

## Этап 1 — bootstrap репозитория

1. Создайте пустой Git-репозиторий.
2. Положите в корень всё содержимое этого pack.
3. Откройте Codex в репозитории.
4. Отправьте ему содержимое `prompts/01_BOOTSTRAP_REPO.md`.
5. После успешного bootstrap сделайте commit.

На этом этапе агент не должен реализовывать продукт целиком. Он создаёт рабочий технический каркас, Docker, зависимости и структуру, сохраняя спецификации.

## Этап 2 — реализация в новом чате

Откройте новый чат Codex в том же репозитории и отправьте `prompts/02_IMPLEMENT_MVP.md`.

Новый агент должен считать `AGENTS.md` и `docs/*` источником истины и довести MVP до end-to-end состояния.

## Приоритет документов

1. `docs/00_CASE_REQUIREMENTS.md` — обязательные правила кейса.
2. `docs/01_PRODUCT.md` — что строим.
3. `docs/02_DOMAIN.md` + `docs/03_STATE_MACHINE.md` — семантика и состояния.
4. `docs/05_PRODUCT_DECISIONS.md` — уже принятые решения.
5. `docs/10_ACCEPTANCE_CRITERIA.md` — что считается готовым.
6. Остальные документы уточняют реализацию.

`AGENTS.md` — основной repo-level instruction file. Критические инструкции не зависят от локального `.codex/` или отдельного `CODEX.md`.
