# ДВИЖ — проверка интерфейса после продуктовой пересборки

Playwright управлял установленным Chrome. На ширинах **320, 360, 390, 430 и 1280 px** открыт главный экран: горизонтального переполнения нет. Снимки сняты с реально отрисованного React-интерфейса, но ответы `/api/v1/*` **мокнуты**; это не проверка внешних MAX/KudaGo.

Пройдено: первое появление подсказки, создание компании, подача сигнала с выбором направления и занятия, отдельные проверки двух занятий как OR и wildcard-направления, конечный набор карточек, pointer-свайп вправо и кнопка пропуска, all-pass, состояние «Выбрано: 1» без автоматического запуска, явный запуск, ответы B/C без собственных сигналов, финальные подтверждения A/B/C, «ДВИЖ СОБРАЛСЯ», вкладки «Движи» и «Компания», недоступный источник, ручной поиск места по названию и явное согласие на `NEAR`. В браузере не было ошибок JavaScript. Ширина 320 запускалась с `prefers-reduced-motion: reduce`; карточка с длинным названием отдельно проверена на отсутствие горизонтального переполнения при 320 px.

Снимки: [главная](docs/dvizh-qa/home-390.png), [кандидат с длинным названием](docs/dvizh-qa/candidate.png), [собрались](docs/dvizh-qa/gathered.png), [недоступный источник](docs/dvizh-qa/provider-unavailable.png). Скриншоты показывают тестовые данные, а не KudaGo. Проверка реальных записей отдельно получила 65 классифицированных квестов для Москвы и один результат ручного поиска по названию через KudaGo.

Отдельно поднят API на чистой PostgreSQL базе `max_dvizh_smoke`: миграции от base до `20260924_0011` и серверный старт прошли. Скрипт `backend/scripts/smoke_dvizh.py` прошёл через реальные HTTP endpoints и KudaGo: A создал компанию и сигнал с 53 доступными карточками квестов, B/C до запуска не видели приватный раунд (404), повтор `X-Request-ID` не создал сигнал, после явного запуска B/C без собственных сигналов ответили, три soft-реакции дали match, три финальных подтверждения дали `GATHERED` с тремя участниками. Два обнаруженных этим прогоном дефекта — раннее создание таблиц bootstrap-миграцией и неверная интерпретация `GMT+03:00` — исправлены.

Frontend `npm run check` проходит формат, lint, typecheck, 34 теста и production build. Backend проходит Ruff, формат, mypy, 74 теста с отдельной PostgreSQL и миграции на PostgreSQL. Compose поднят с API, frontend, worker, scheduler, PostgreSQL, Redis; API и frontend вернули HTTP 200. Живая регистрация MAX webhook и мобильный MAX требуют токен, публичный HTTPS домен и секрет владельца.
